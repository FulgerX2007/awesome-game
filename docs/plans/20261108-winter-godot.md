# «Долгая зима» на Godot 4: перенос и новая графика

## Overview
- Цель — полноценная 2.5D-версия «Долгой зимы» (`/winter/`) на Godot 4.7.2 с видом сверху под небольшим углом,
  стилизованной премиальной графикой (стиль «Stylized Premium Winter Survival»), живым освещением, погодой и новым
  интерфейсом. Правила и баланс остаются прежними: GDScript-порт `web/winter/core.js` играет так же, как веб-версия,
  это доказывает тест паритета.
- Проект — `godot/winter/`, сборка для сайта — `web/winter-godot/` (маршрут `/winter-godot/`), игра запускается
  и прямо в редакторе Godot (F5), и как десктоп-приложение. От браузерной реализации нет зависимостей во время работы:
  правила, данные и графика — свои файлы проекта.
- Веб-версия `/winter/` остаётся как есть (так же сделаны «Глубина», «Тяни штифт», «Последняя крепость»). Убрать её —
  отдельное решение после приёмки Godot-версии.

## Этап 1. Анализ существующей игры

### Движок, язык, структура
- Чистый JavaScript + Canvas 2D, без библиотек. Go-сервер (`main.go`) раздаёт `web/` через `embed`.
- `web/winter/core.js` (1751 строк) — все правила без DOM: карта, время, погода, показатели, действия, постройки,
  верстак, выжившие, звери, волки, медведь, торговец, события, звёзды, сохранение. Мир считается шагом 1/20 с.
- `view.js` — камера, экран ↔ клетки, источники света, темнота, сияние, часы. `game.js` (2503 строки) — экраны,
  панели, ввод, эффекты и вся отрисовка. `audio.js` — синтез звука WebAudio. `lang.js` — RU/RO. `index.html`, `style.css`.
- Тесты `tests/winter/`: правила, события, улучшения, медведь, торговец, звук, вид, сборка; боты `bot.js`
  (жадный, небрежный, без укрытия) проверяют баланс; `smoke.cjs` — Playwright.

### Механики (всё переносится без изменений)
| Механика | Где в core.js | Суть |
|---|---|---|

| Показатели | `statsTick` | тепло, сытость, силы (= «выносливость»), здоровье 0–100; ноль любого показателя отнимает здоровье, всё > 40 — лечит |

| Постройки | `contribute`, `needOf`, `finishStage` | вносятся по частям: хижина в 4 этапа (стены, крыша+кровать, дверь, печь), частокол 4 стены (100 прочности, починка), трое нар, факелы (2 дерева, до 12), улучшения дома |
| Верстак | `craft`, `craftGear` | инструменты: кирка, лопата, ледоруб, копьё, железный топор; снаряжение мастерской: шуба, фонарь, сани, силки |
| Инвентарь | `g.stock`, `g.tools`, `g.gear`, `hero.load` | склад лагеря (материалы + еда), инструменты, снаряжение, ноша героя |
| Выжившие | `rescue`, `survivorsTick` | 5 человек со своими условиями; дома едят, греются, лечатся, работают |
| Звери и враги | `animalsTick`, `wolvesTick`, `bearTick` | зайцы, олени (копьё), волки ночью (боятся света, грызут частокол), медведь-шатун в свои дни |
| События дня | `pickEvent`, `answerEvent` | крыша, путник, ребёнок потерялся, сияние, оттепель/наледь |
| Торговец | `traderArrives`, `trade` | у южных ворот в свои дни, 3 случайных обмена + 1 постоянный |
| Победа | `stars`, `recordGame` | ★ дожил, ★★ спас ≥ 3, ★★★ все пятеро и хижина целиком; «Лютая зима» после первой весны |

### Соответствие требований задачи и игры
- «Выносливость» — это показатель «Силы» (`energy`): тратится на работу, восстанавливается сном и отдыхом у огня.
- «Хранилище» — склад лагеря; улучшение «Погреб» добавляет место для еды. «Стены, ограждения, ворота» — четыре стены
  частокола, у южной стены рисуются ворота. «Фундамент» — первая стадия хижины (стены начинаются с венца на камнях).
- Состояния построек: строится (внесено частично — видны леса и часть брёвен), готово, повреждено (частокол < 100,
  дыра в крыше), разрушено (частокол с прочностью 0).
- Свободно ставятся только факелы и силки: для них прозрачный предпросмотр и подсветка «можно / нельзя».
  Остальные постройки стоят на своих местах лагеря; в меню построек их место подсвечивается призраком.
- Новое только в оформлении: окно инвентаря, окно рецептов, настройки (звук, язык, качество погоды и света, размер
  интерфейса). «Обычный снег» и «сильный снегопад» — чисто визуальные; на правила влияет только метель (как в вебе).

### Найденные ошибки (исправляются отдельно, не в визуальной переработке)
- `game.js` `handle()`: ветка `case 'smoked'` записана дважды, вторая недостижима. Безвредно, в порт не переносится.
- Остальные — по мере порта: каждая записывается сюда с решением.

## Этап 1. Архитектура Godot-версии

### Решения
- **2D, не 3D.** Вид сверху под углом «три четверти», как в вебе: правила остаются на сетке, объекты растут вверх
  от клетки. 2D даёт нужный результат: объём рисуется в спрайтах (мягкое затенение, свет сверху слева, контактная
  тень), а **карты нормалей** у спрайтов дают живой свет огня на снегу, деревьях и людях через `PointLight2D`.
  Полное 3D дороже для веба и ничего не добавляет игровому процессу.
- **Рендер GL Compatibility** — работает и в браузере (WebGL 2), и на слабых ПК.
- **Правила отдельно от графики.** `scripts/sim/sim.gd` — порт `core.js` строка в строку: те же функции над
  тем же словарём состояния (ключи как в JS), без узлов и без `Vector2` (только `float` двойной точности).
  Отсюда снимок сохранения совместим с JSON веб-версии.
- **Тест паритета** (как у «Глубины»): жадный бот веб-версии играет в Node, его вызовы API записываются по тикам,
  Godot воспроизводит их на порте и сравнивает состояние каждую игровую секунду. Совпадение = баланс не изменился.
  Поэтому ботов баланса в GDScript не переносим: их выводы наследуются через паритет.
- **Данные — ресурсы Godot.** `data/*.tres`: предметы (`WinterItemDef`), рецепты верстака (`WinterRecipeDef`),
  постройки (`WinterBuildingDef`), параметры баланса (`WinterBalance`). Их генерирует `tools/winter-godot/data.cjs`
  из констант `core.js`; тест проверяет, что файлы свежие. Правила читают ресурсы через `WinterData`.
- **Земля — шейдер**, а не `TileMapLayer`. Типы клеток лежат в маленькой текстуре данных 56×40, шейдер рисует плавные
  переходы снега, глубокого снега, льда и утоптанной земли лагеря, наст, искры и мягкие неровности по шуму без
  видимых повторов. Сугроб, раскопанный лопатой, меняет один пиксель текстуры. `TileMapLayer` потребовал бы
  автотайлов с переходами на каждую пару поверхностей и всё равно давал бы сетку.
- **Сортировка по глубине** — встроенный Y-sort Godot: у каждого спрайта точка опоры в ногах.

### Сцена и слои
```
Main (Node, main.gd: экраны, ввод, сохранения)
├── World (Node2D, world.gd)                     ← CanvasModulate (день/ночь) действует на весь мир
│   ├── Ground          z −30  шейдер земли, снег, лёд, проруби
│   ├── GroundDetails   z −20  следы ног, следы зверей, пятна земли, ветки, силки, метки клика
│   ├── Shadows         z −10  мягкие тени объектов (по солнцу; ночью гаснут)
│   ├── Entities        y-sort
│   │   ├── WorldObjects  y-sort  деревья, камни, кусты, постройки, костёр, факелы, сани торговца
│   │   └── Characters    y-sort  герой, выжившие, звери, волки, медведь, путник
│   ├── Effects         z +10  частицы огня, дыма, искр, щепок, дыхания, всплывающие числа
│   ├── Weather         z +20  падающий снег (в мире: его освещает костёр), позёмка
│   └── Lights                 PointLight2D: костёр, печь, факелы, фонарь (не больше 16)
├── Atmosphere (CanvasLayer 1)  туман метели, виньетка, сияние, вспышка урона
└── UI (CanvasLayer 10, ui.gd)  HUD, панели, меню, пауза, настройки
```

### Скрипты
- `scripts/sim/` — правила: `sim.gd` (порт), `rng.gd` (mulberry32 бит в бит), `data.gd` (`WinterData`),
  `defs/*.gd` (классы ресурсов). Ничего не знают об узлах.
- `scripts/world/` — вид: `world.gd` (сборка слоёв, синхронизация с состоянием), `ground.gd` + `shaders/ground.gdshader`,
  `props.gd` (узлы, декор, постройки), `actors.gd` (люди и звери на `AnimatedSprite2D`), `lights.gd`,
  `weather.gd`, `fx.gd` (пулы частиц и следов), `camera.gd` (плавное следование, границы карты).
- `scripts/ui/` — `hud.gd`, `panels.gd` (постройки, верстак, инвентарь, торговец, событие), `menu.gd`, `theme.gd`.
- `scripts/app/` — `main.gd`, `store.gd` (localStorage в браузере, `user://` на ПК), `save.gd`, `sfx.gd` (синтез звука), `i18n`.
- Каждый кадр мир только читает состояние; тяжёлое (пути A*, маски волков) — внутри шага правил, как в вебе.

### Ассеты
- Масштаб: **1 клетка = 96 px** мировых и текстурных (без масштабирования спрайтов). Герой ~1,35 клетки ростом.
  Точка опоры каждого спрайта — середина контакта с землёй (`foot`).
- Свет нарисован сверху слева (направление к свету `(-0.55, -0.65, 0.52)`), палитра — `tools/winter-godot/palette.py`
  (общая для всех генераторов). Не пиксель-арт, без чёрных контуров: мягкая тёмная кромка того же оттенка.
- Свои ассеты генерирует код (`tools/winter-godot/art/*.py`, PIL + numpy) по полям высот: из них считаются цвет
  с мягким светом и окклюзией, карта нормалей и тень. Это даёт единый стиль и варианты без повторов.
  Внешние наборы — только с лицензией для коммерческого использования, с записью в `godot/winter/ASSET_LICENSES.md`
  (шрифт Golos Text, OFL, уже есть в проекте).
- Структура `godot/winter/assets/`: `characters/{player,survivors,animals}`, `environment/{trees,rocks,bushes,snow,ground}`,
  `buildings`, `resources`, `effects/{fire,smoke,snow,weather}`, `ui/{icons,panels,buttons,indicators}`, `audio`, `fonts`.
- Каталог `assets/manifest.json` (пишут генераторы): ключ → файл, карта нормалей, размер, `foot`, кадры анимаций.
  Код вида берёт спрайты только по ключам.

## Testing Strategy
- `godot --headless --path godot/winter -s res://tests/run.gd` — правила, данные, сохранение, переводы.
- `node --test tests/winter-godot/` — свежесть данных, паритет с `core.js` (с `GODOT`), веб-сборка на месте.
- `godot --headless --path godot/winter -s res://tests/scenes.gd` — настоящие сцены: меню, игра, ночь, метель,
  окна, сохранение и загрузка; любой `SCRIPT ERROR` валит CI.
- `xvfb-run … tests/shot.gd` — кадры для глаз (день, ночь у костра, метель, меню, телефонный экран).
- Существующие `go test ./...` и `node --test 'tests/**/*.test.js'` зелёные на каждом шаге.
